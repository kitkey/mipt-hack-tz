# Демонстрация

Содержательную проверку делает только модель. Без `TZCHECK_LLM_MODEL` и ключа система только разбирает документ и проверяет его на скрытые символы и инструкции для ИИ, замечаний по требованиям в этом случае нет. Как задать модель, написано в README репозитория, в разделе "Быстрый старт".

Отчёты в `output/` собраны 14.11.2026 на демо-стенде сборкой 270dba2. Поиск замечаний делала deepseek/deepseek-v4.1-flash, вторую проверку делали две модели (вторая qwen/qwen3.8-27b). Справочники брались из локальной копии, пункты норм искал BM25.

## Прогон через Docker и API

Прогон запускается командой `sh demo/run_demo.sh` (Linux, macOS, Git Bash) или `powershell -File demo/run_demo.ps1` (Windows), результаты пишутся в `demo/out/`. Порт берётся так же, как у `docker compose`, из `APP_PORT` в окружении, иначе из `.env`, иначе 8000.

| Шаг | Что делает |
|---|---|
| 1 | `docker compose up -d --build app`, ждёт `/health` |
| 2-4 | `POST /api/check` с `public=1` для `samples/lift_src.docx`, `samples/metro_src.docx`, `samples/lift_fin.docx`, с моделью, если она задана |
| 5 | `POST /api/compare?use_llm=true` для `samples/lift_src.docx` и `samples/lift_fin.docx`; с внешней моделью нужен `TZCHECK_DOC_PUBLIC=1` в `.env` или слой NER, у сравнения флага `public` нет |
| 6 | пустой файл: ответ 400 с причиной |
| 7 | CLI в контейнере с `TZCHECK_DOC_PUBLIC=1`: JSON, HTML, docx с комментариями и docx с правками |

Образцы кейса помечаются открытыми, потому что в них нет персональных данных. Без пометки внешняя модель без слоя NER не вызывается.

## Что лежит в `output/`

| Папка | Вход | Время | Основной список | На проверку |
|---|---|---|---|---|
| `01_metro_src` | `samples/metro_src.docx`, ТЗ на поставку метрологического оборудования | 7 мин | 2 | 56 |
| `02_lift_src` | `samples/lift_src.docx`, ТЗ на замену грузового лифта | 15 мин | 11 | 51 |

В каждой папке лежат отчёт `*.report.json` и `*.report.html`, Word с комментариями у абзацев и строк таблиц `*.comments.docx` и журнал вызовов модели с маской ПД `*.trace.json`. Word с правками в режиме рецензирования `*.revisions.docx` есть только у лифта: правки в него идут из замечаний основного списка с точной заменой, у двух замечаний метрологии замены нет. `summary.json` сводит число замечаний по папкам.

## Пересборка

`python demo/build_demo.py` проверяет моделью сценарии из скрипта и пишет их папки в `output/`. Без заданной модели скрипт останавливается, вызовы модели платные. Все входы открытые (образцы кейса и ТЗ из ЕИС), поэтому скрипт помечает их `public=True` и ставит `TZCHECK_DOC_PUBLIC=1`. Исходники ТЗ из ЕИС в репозиторий не входят, потому что в них контакты сотрудников заказчиков, и без них сценарии по ЕИС не запускаются. `python demo/run_llm_cases.py` прогоняет `lift_src` и `lift_fin` на локальной модели через OpenAI-совместимый сервер.
