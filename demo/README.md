# Демонстрация

Проверка содержательная только с моделью: без `TZCHECK_LLM_MODEL` и ключа документ разбирается и проверяется на скрытые символы и инструкции для ИИ, замечаний по требованиям нет. Как задать модель, в README репозитория, раздел «Быстрый старт».

**Готовые отчёты в `output/` собраны прежней версией системы (правила без модели, сценарии 16-19 с локальной моделью поверх правил) и будут пересобраны.** Их содержимое (число и состав замечаний, вердикты, время) к текущей проверке не относится.

## Прогон через Docker и API

`sh demo/run_demo.sh` (Linux, macOS, Git Bash) или `powershell -File demo/run_demo.ps1` (Windows). Результаты в `demo/out/`. Порт берётся так же, как у `docker compose`: `APP_PORT` из окружения, иначе из `.env`, иначе 8000.

| Шаг | Что делает |
|---|---|
| 1 | `docker compose up -d --build app`, ждёт `/health` |
| 2-4 | `POST /api/check` с `public=1` для `samples/lift_src.docx`, `samples/metro_src.docx`, `samples/lift_fin.docx`: проверка моделью, если она задана |
| 5 | `POST /api/compare?use_llm=true` для `samples/lift_src.docx` и `samples/lift_fin.docx`; с внешней моделью нужен `TZCHECK_DOC_PUBLIC=1` в `.env` или слой NER, у сравнения флага `public` нет |
| 6 | пустой файл: ответ 400 с причиной |
| 7 | CLI в контейнере с `TZCHECK_DOC_PUBLIC=1`: JSON, HTML, docx с комментариями и docx с правками |

Образцы кейса помечаются открытыми: в них нет персональных данных, а без пометки внешняя модель без слоя NER не вызывается.

## Пересборка `output/`

`python demo/build_demo.py` проверяет моделью все сценарии ниже и перезаписывает их папки. Скрипт останавливается, если модель не задана; вызовы модели платные. Все входы открытые (образцы кейса и ТЗ из ЕИС), поэтому скрипт помечает их `public=True` и ставит `TZCHECK_DOC_PUBLIC=1`.

| Папка | Вход |
|---|---|
| `01_metro_src` | `samples/metro_src.docx`, ТЗ на поставку метрологического оборудования, исходное |
| `02_lift_src` | `samples/lift_src.docx`, ТЗ на замену грузового лифта, исходное |
| `03_lift_src_pdf` | `samples/pdf/lift_src.pdf`, то же ТЗ в PDF |
| `04_lift_fin` | `samples/lift_fin.docx`, итоговое ТЗ лифта после правок закупщиков |
| `05_metro_fin` | `samples/metro_fin.docx`, итоговое ТЗ метрологии |
| `06_compare_metro` | сравнение `metro_src` и `metro_fin` |
| `07_eis_server_msu` ... `11_eis_lift_with_appendices` | ТЗ из ЕИС (сервер, ремонт помещений, клининг, медицинское оборудование, лифт с тремя приложениями) |
| `12_broken_files` | пустой docx, текст с расширением docx, обрезанный PDF |
| `13_lift_src_rag` | `samples/lift_src.docx` с `TZCHECK_RAG=1` (пункты норм, BM25) |
| `15_injection` | `samples/injection.docx`, итоговое ТЗ лифта со скрытой инструкцией для ИИ и символами нулевой ширины |

Исходники ТЗ из ЕИС в репозиторий не входят (в них контакты сотрудников заказчиков): без них папки `07`-`11` не пересобираются и остаются от прежней версии. В отчётах по ЕИС ПД заменены метками `[PERSON_1]`, `[PHONE_1]`, comments.docx для них не создаётся.

`14_lift_scan_ocr` собирается в образе с `WITH_OCR=1` (`samples/scan/lift_src_scan.pdf` через `/api/check`); `build_demo.py` только подхватывает готовый отчёт в `summary.json`. `16`-`19` собирал `python demo/run_llm_cases.py` с локальной моделью (Qwen3.8-27B на OpenAI-совместимом сервере), по две оркестрации `linear` и `graph` для `lift_src` и `lift_fin`.
