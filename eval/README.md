# Оценка качества

Замер прежней версии на правилах, её код удалён 14.11.2026; текущая проверка моделью описана в README.

На текущей версии эти цифры не пересчитывались. Все прогоны ниже шли в режиме правил без модели, справочники брались из локальных копий. Перед запуском выполнить `export TZCHECK_REFDATA_OFFLINE=1` (Windows: `$env:TZCHECK_REFDATA_OFFLINE=1`), в Docker замер запускает `docker compose exec app python eval/eval_labels.py`.

## 105 правок закупщиков: `eval_labels.py`

Замер идёт на двух парах "исходное / итоговое" ТЗ из кейса (`samples/lift_src.docx` и `lift_fin.docx`, `metro_src.docx` и `metro_fin.docx`). Для каждой правки закупщика в `labels.csv` записаны место, класс из 10 категорий, было, стало, почему ошибка, основание. У лифта 13 правок, у метрологии 92.

Метрики:

| Метрика | Условие засчёта | Результат |
|---|---|---|
| По месту | есть замечание в том же абзаце или строке таблицы | 97/105 = 92 % |
| С верной категорией | то же место и та же категория | 92/105 = 88 % |
| Строго | то же место, та же категория, цитата про размеченный фрагмент | 84/105 = 80 % |
| Ложные на итоговых | число замечаний на итоговых ТЗ после правок закупщиков | лифт 7 (высоких 3), метрология 8 (высоких 0) |

Для 5 правок место в исходных документах автоматически не находится (абзац переписан целиком), эти правки остаются в знаменателе как промах.

По категориям, строго / всего: неполнота или комплектность 22/30, ограничение конкуренции 15/18, стандарты 11/16, ОКПД 2 11/11, некорректная характеристика 9/10, лишнее в ТЗ 6/8, оформление 3/3, предмет закупки 1/3, противоречие 3/3, гарантия 3/3.

Три высоких замечания на итоговом ТЗ лифта стоят на фрагментах, которые закупщики не исправили. Это модель кнопок BW-1 без "или эквивалент", ГОСТ Р 28911-2015 и ГОСТ Р 34441-2018 (таких национальных стандартов нет, межгосударственные с теми же номерами заменены по каталогу Росстандарта).

Правила вместе с моделью (Qwen3.8-27B, сохранённый прогон 3) на тех же 105 правках дали строго 78/105, по месту 97/105, с категорией 86/105, на итоговых ТЗ 45 замечаний у лифта и 27 у метрологии. Модель без калибровки добавляет шум, поэтому по умолчанию отчёт строится на правилах.

## Синтетические дефекты: `synth_defects.py`

В итоговые ТЗ по одному вставляются дефекты 11 видов (марка без эквивалента, "референс", "по возможности", рабочая пометка, документация только на английском, срок без даты начала, несуществующий код ОКПД 2, код другого товара, удалённая гарантия, инструкция для ИИ в тексте, скрытый Unicode). Дефект засчитывается, если на вставленном месте появилось замечание нужного вида. Результат 21/22 = 95 %. Пропущен код ОКПД 2 другого товара в metro_fin. Скрытый символ ловит предупреждение безопасности.

## Сверка частей и файлов: `reconcile/`

Сверка частей прежней версии нашла 60 из 60 противоречий, вставленных в lift_fin, metro_fin и три ТЗ ЕИС (12 видов по 5 подобранных случаев), и на ручной разметке кандидатов сверки трёх исходных ТЗ ЕИС дала точность 2/2. В репозитории лежат результаты `result.json` и `result_extended.json`, разметка `manual_labels.csv` и `split_eis.py`, который делит открытые DOCX из ЕИС на основной файл и приложения по исходным границам. Скрипты замера прежней версии на правилах удалены вместе с кодом.

## ТЗ из ЕИС без разметки

Набор из 9 ТЗ других заказчиков охватывает сервер (МГУ), ремонт помещений (МТУСИ), стоматологические изделия, замена лифта, метрологическая лаборатория, лабораторное оборудование, интраоральный сканер, нейродиагностика, секвенирование. Все замечания со статусом "ошибка" и с высоким риском просмотрены вручную, причины ложных срабатываний исправлены в правилах (обозначения интерфейсов и инструкций процессора как марки, расписания значений как противоречия, лист согласования и проект договора как повтор раздела). После проверки обобщения (ниже) осталось 64 замечания, из них со статусом "ошибка" 1 и с высоким риском 1. Корпус в репозиторий не входит (в нём контакты сотрудников заказчиков), отчёты по 4 ТЗ с маскированием ПД лежат в `demo/output/`.

## PDF, сканы и пункты норм

Методика и полные таблицы лежат в `ocr_compare/` (текстовый PDF против docx, OCR по страницам, сканы целиком) и `rag/` (421 вопрос, поиск по корпусу и путь в конвейере проверки). Короткая сводка есть в README, в разделах "Сканы" и "Пункты норм".

| Что | Результат |
|---|---|
| Текстовый PDF против docx, 4 пары | CER 0,06-1,09 %, замечаний совпало 18/18, 91/92, 7/7, 8/8 |
| OCR страниц 150 dpi, чистые / искажённые | CER 1,06 % / 1,77 %, коды ОКПД 2 100 % |
| Скан целиком против docx | lift_src 15/18, metro_src 78/92 |
| Гибрид BM25 + USER-bge-m3 по всему корпусу | R@5 0,345, MRR@10 0,250 |
| Пункт нормы к правкам закупщиков | верный 12/77, неверный 1 |
| Отказ на вопросах без ответа | сбалансированная точность 0,50-0,52, не отличает |
