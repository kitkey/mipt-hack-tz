# Оценка качества

Все прогоны ниже в режиме правил без модели, справочники из локальных копий. Перед запуском: `export TZCHECK_REFDATA_OFFLINE=1` (Windows: `$env:TZCHECK_REFDATA_OFFLINE=1`). В Docker: `docker compose exec app python eval/eval_labels.py`.

## 105 правок закупщиков: `eval_labels.py`

Данные: две пары «исходное / итоговое» ТЗ из кейса (`samples/lift_src.docx` и `lift_fin.docx`, `metro_src.docx` и `metro_fin.docx`). Каждая правка закупщика размечена в `labels.csv`: место, класс из 10 категорий, было, стало, почему ошибка, основание. Лифт 13 правок, метрология 92.

Метрики:

| Метрика | Условие засчёта | Результат |
|---|---|---|
| По месту | есть замечание в том же абзаце или строке таблицы | 97/105 = 92 % |
| С верной категорией | то же место и та же категория | 92/105 = 88 % |
| Строго | то же место, та же категория, цитата про размеченный фрагмент | 84/105 = 80 % |
| Ложные на итоговых | число замечаний на итоговых ТЗ, где закупщики уже всё исправили | лифт 7 (высоких 3), метрология 8 (высоких 0) |

Место 5 правок в исходных документах автоматически не находится (абзац переписан целиком), они остаются в знаменателе как промах.

По категориям, строго / всего: неполнота или комплектность 22/30, ограничение конкуренции 15/18, стандарты 11/16, ОКПД 2 11/11, некорректная характеристика 9/10, лишнее в ТЗ 6/8, оформление 3/3, предмет закупки 1/3, противоречие 3/3, гарантия 3/3.

Три высоких замечания на итоговом ТЗ лифта стоят на фрагментах, которые закупщики не исправили: модель кнопок BW-1 без «или эквивалент», ГОСТ Р 28911-2015 и ГОСТ Р 34441-2018 (таких национальных стандартов нет, межгосударственные с теми же номерами заменены по каталогу Росстандарта).

Правила и модель на тех же 105 правках (Qwen3.8-27B, сохранённый прогон 3): строго 78/105, по месту 97/105, с категорией 86/105; на итоговых ТЗ 45 замечаний у лифта и 27 у метрологии. Модель без калибровки добавляет шум, поэтому по умолчанию отчёт строится на правилах.

## Синтетические дефекты: `synth_defects.py`

В итоговые ТЗ по одному вставляются 11 видов дефектов: марка без эквивалента, «референс», «по возможности», рабочая пометка, документация только на английском, срок без даты начала, несуществующий код ОКПД 2, код другого товара, удалённая гарантия, инструкция для ИИ в тексте, скрытый Unicode. Засчитывается, если на вставленном месте появилось замечание нужного вида. Результат 21/22 = 95 %. Пропуск: код ОКПД 2 другого товара в metro_fin. Скрытый символ находится предупреждением безопасности.

## Сверка частей и файлов: `reconcile/`

`evaluate_extended.py` вставляет 60 противоречий 12 видов по 5 случаев: значение, диапазон, количество, срок поставки, гарантия, срок и форма приёмки, комплектность, единицы, отсутствующее приложение, содержание, дублирование раздела. Документы: lift_fin, metro_fin и три ТЗ ЕИС; парные вставки разнесены между основным файлом и приложением. Результат 60/60. Ссылки одного документа на отсутствующие приложения сводятся в одно замечание, номер может стоять в перечне объяснения. Без вставок на lift_fin и metro_fin 0 замечаний сверки.

`score_manual.py`: все кандидаты сверки на трёх исходных ТЗ ЕИС размечены вручную в `manual_labels.csv`, точность 2/2: два замечания о 5 ссылках на приложения, которых нет среди переданных файлов. Выборка мала и не оценивает точность других видов.

Это тест подобранных формулировок, а не оценка полноты на произвольных документах.
